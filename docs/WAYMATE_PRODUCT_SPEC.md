# Waymate 最小产品基线

**文档状态：** 初始基线

**当前原则：** 第一版仍以 iPhone 为主；硬件型号尚未最终确定；现有 1.75C 兼容性需要保留；不在本阶段修改 ESP32 硬件驱动、BLE 协议或现有功能代码。

## 1. 产品定位

Waymate 是一个面向骑行场景的圆屏导航设备及手机协同系统。第一版建立在当前 MOTO GPS 衍生项目上，优先保持已有的 iPhone 导航体验，再逐步增加独立 GNSS、轨迹记录和原路回溯能力。

第一版不把设备定义为完整的独立手机替代品。搜索、路线规划和主要导航决策仍以 iPhone 为主；设备侧逐步增加定位、记录和回溯能力。

## 2. 已有功能基线

| 功能 | 主要归属 | 是否需要 GNSS | 第一版处理 |
|---|---|---:|---|
| iPhone 通过 BLE 向圆屏发送导航信息 | 手机 + 设备 | 否，使用手机导航结果 | 保留 |
| 转向、距离、速度、方向显示 | 设备显示；数据主要来自手机 | 否；独立设备数据模式需要 GNSS | 保留 |
| 466×466 圆屏触摸 UI | 设备本地 | 否 | 保留 |
| BLE 通信 | 手机 + 设备 | 否 | 保留 |
| iOS 搜索、路线和导航 | 手机 | 否，定位由现有 iPhone 方案提供 | 保留，iPhone 为第一优先平台 |
| 音乐控制 | 手机 + 设备交互 | 否 | 保留；第一版继续以 iPhone 能力为准 |
| IMU | 设备本地 | 否 | 保留，用于方向辅助和运动感知 |

已有导航显示继续采用当前“手机计算、设备显示”的基本模式，不因为计划增加 GNSS 就立即改动现有导航链路。

## 3. 计划新增功能

| 功能 | 主要归属 | 是否需要 GNSS | 规划状态 |
|---|---|---:|---|
| 独立 GNSS | 设备本地 | 是 | 计划功能，等待硬件型号确定 |
| 骑行轨迹记录 | 设备本地；后续可与手机同步 | 是 | 计划功能，依赖稳定 GNSS |
| 类 Apple Watch Backtrack 原路回溯 | 设备本地为主 | 是 | 计划功能，依赖轨迹记录 |
| 骑行里程、速度等数据 | 设备本地优先，手机可辅助 | 独立统计需要 GNSS | 计划功能，先做基础统计 |
| “Can you hear me?” 同行骑手提示 | 手机 + 设备；后续可能扩展为同行会话 | 否 | 计划功能，先做短提示，不预设语音通话 |
| Android / 荣耀手机支持 | 手机端 | 否；若使用设备 GNSS则由协议提供 | 可选后续方向，不属于第一版交付范围 |

### 3.1 独立 GNSS

独立 GNSS 的目标是让设备在不完全依赖手机定位的情况下获得有效位置，并为轨迹、里程和回溯提供统一位置来源。

第一阶段只定义能力边界，不预设具体硬件实现：

- 需要等 1.75C 或 1.75-G 型号确定后，再确认 GNSS 芯片、接口、天线和供电；
- GNSS 数据应保留有效性、时间、精度、速度和航向等状态；
- 设备 GNSS 与手机定位之间的优先级和回退策略需要单独设计；
- 在硬件未到位前，不修改现有硬件驱动和 BLE 协议。

### 3.2 轨迹记录

轨迹记录的最小目标是保存一次骑行中的连续定位点，并能够查看、清除或导出记录。第一版不要求立即实现复杂地图展示或云端同步。

轨迹记录需要 GNSS。手机定位可以作为临时或回退来源，但不能替代“独立 GNSS”产品目标。

### 3.3 Backtrack

Backtrack 的最小定义是：设备根据当前骑行中已经记录的轨迹，给出返回起点或沿原路返回的方向和距离提示。

第一版不承诺完整离线地图导航，也不承诺复杂的道路重规划。应先解决轨迹采样、噪声过滤、定位丢失、环路和轨迹存储问题。

### 3.4 骑行数据

第一版优先考虑：

- 本次骑行里程；
- 当前速度；
- 平均速度；
- 骑行时间；
- 定位有效时间和无效时间。

其中独立设备统计需要 GNSS。现有导航页面中的速度显示可以继续使用手机提供的数据，不必等待独立 GNSS 完成。

### 3.5 “Can you hear me?”

第一版将其定义为同行骑手之间的短提示事件，而不是即时语音通信：

- 能发送提示；
- 能接收提示；
- 能显示或播放简单确认；
- 具备限频、会话和权限边界。

是否加入麦克风、蓝牙音频或双向语音，暂不纳入最小基线。

## 4. 设备本地功能与手机依赖

### 4.1 设备本地功能

- 圆屏显示、触摸和页面切换；
- BLE 连接状态和设备侧通信；
- IMU 采样和方向辅助；
- 未来的独立 GNSS 接收；
- 未来的轨迹采样、存储和回溯提示；
- 未来的基础里程、速度和骑行时间统计。

### 4.2 依赖手机的功能

- 地点搜索；
- 路线规划和路线选择；
- iPhone 导航状态产生；
- 现有地图和后端服务；
- 第一版的主要定位回退能力；
- Apple Music 等 iOS 音乐控制；
- 第一版的同行提示会话管理。

### 4.3 两端共同承担的功能

- BLE 连接和数据传输；
- 导航状态同步；
- 未来的 GNSS 数据同步；
- 轨迹导出、查看和管理；
- 同行骑手提示的发送、接收和确认。

## 5. 暂时明确不做

以下内容不属于当前最小开发基线：

- 现在开始 1.75-G 适配；
- 修改现有 ESP32 硬件驱动；
- 修改或扩展当前 BLE 协议；
- 在没有硬件验证前实现正式 GNSS 驱动；
- 独立于手机的完整搜索、路线规划和地图系统；
- 第一版 Android 或荣耀手机正式支持；
- 即时语音通话或复杂音频通信；
- 云端账号、社交网络和骑行数据平台；
- 大规模 MOTO GPS → Waymate 重命名；
- 删除或替换 LICENSE、NOTICE 和原作者署名。

## 6. 当前技术边界

当前代码仍以 Waveshare 1.75C 和 iPhone 为主要基线。1.75C 与 1.75-G 的最终选择尚未完成，因此产品文档先描述能力和依赖关系，不把任何一个型号写成已经确定的硬件事实。

Waymate 的第一版应优先保证：现有 iPhone 导航链路不被破坏、圆屏 UI 和 BLE 能力可持续复用、未来 GNSS 和轨迹功能可以在硬件型号确定后接入。

原项目的 LICENSE、NOTICE、作者署名和第三方许可证继续有效，本产品基线不改变这些要求。
