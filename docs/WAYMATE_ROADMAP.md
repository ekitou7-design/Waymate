# Waymate 最小开发路线图

**路线图状态：** Waymate v1 第一版规划

**目标硬件：** Waveshare ESP32-S3-Touch-AMOLED-1.75C（带电池版本）

**总原则：** 保持现有 1.75C 项目稳定，以 iPhone 作为主要定位、联网和导航来源，把圆屏定位为骑行 Companion Display。第一版不做设备端独立 GNSS；iPhone 轨迹记录是轨迹显示和 Backtrack 的基础，Android 属于后续可选支持。

本路线图不授权提前修改 ESP32 硬件驱动、BLE 协议或大规模项目重命名。每个阶段完成后再决定是否进入下一阶段。

## Phase 0：现有项目基线

### 目标

保持当前 Waveshare 1.75C 项目正常，冻结可复用能力和边界，保证后续 Waymate 工作不会破坏已有的 iPhone 导航产品。

### 保留内容

- iPhone 搜索、路线和导航；
- iPhone → BLE → 圆屏导航信息链路；
- 转向、距离、速度、方向显示；
- 466×466 圆屏触摸 UI；
- BLE 通信；
- 音乐控制；
- IMU 方向辅助；
- 现有共享导航核心、UI、测试和后端能力。
- 1.75C 的现有 ESP32 board port、sdkconfig、分区和组件基线。

### 阶段边界

- 不修改 ESP32 硬件驱动；
- 不修改 BLE 协议；
- 不进行 1.75-G 适配，也不引入设备端独立 GNSS；
- 不进行大规模 MOTO GPS → Waymate 重命名；
- 保留 LICENSE、NOTICE、原作者署名和第三方许可证。

### 完成条件

现有 1.75C 固件、iPhone BLE 导航链路和圆屏 UI 保持可用，并完成 Waymate v1 的产品边界确认。

## Phase 1：Waymate 品牌和 UI

### 目标

在不改变 1.75C 硬件基线和核心导航行为的前提下，建立 Waymate 的品牌和圆屏视觉语言。

### 需要确认

- Waymate 设备名称、启动页、连接页和页面标题；
- 导航、轨迹、回溯、音乐和骑行数据的页面层级；
- 圆屏在骑行中的信息优先级和低干扰交互；
- 现有 MOTO GPS 上游署名、LICENSE、NOTICE 和第三方版权信息的保留位置。

### 阶段边界

不修改 ESP32 board port、BLE 协议或 iOS 功能代码；品牌替换采用受控范围，不进行大规模历史名称清理。

### 完成条件

形成 Waymate v1 的 UI 基线和页面验收清单，并确保现有 1.75C 固件仍可运行。

## Phase 2：iPhone 轨迹记录

### 目标

让 iPhone 能够稳定记录一次骑行轨迹，并完成轨迹生命周期管理。

### 工作内容

- 定义轨迹点、时间戳、精度、速度和方向字段；
- 支持开始、暂停、继续、结束和异常中断；
- 保存、查看、清除和导出轨迹；
- 处理权限、后台定位、定位丢失和低精度点；
- 明确轨迹隐私和本地数据删除策略。

### 阶段边界

轨迹全部以 iPhone 定位为来源，不增加设备端 GNSS，不修改 ESP32 硬件驱动。

### 完成条件

一次正常 iPhone 骑行结束后，轨迹能够完整保存、读取、清除并导出。

## Phase 3：圆屏轨迹显示

### 目标

让圆屏在骑行过程中显示来自 iPhone 的轨迹摘要、当前位置和必要的轨迹窗口。

### 工作内容

- 定义适合圆屏的轨迹显示层级；
- 明确当前位置、已走轨迹、剩余路线和导航提示的视觉优先级；
- 由 iPhone 负责轨迹数据和定位状态，圆屏负责低干扰显示；
- 验证断连、无轨迹、低精度和轨迹结束状态的显示。

### 阶段边界

不在设备端保存完整轨迹数据库，不引入独立 GNSS，不把圆屏变成独立地图终端。传输方式如需扩展，另行评估 BLE 协议影响。

### 完成条件

圆屏能够稳定显示 iPhone 提供的轨迹状态，并在手机断连或轨迹无效时给出明确状态。

## Phase 4：Backtrack

### 目标

基于 iPhone 已记录的轨迹，支持沿原路返回的提示。

### 工作内容

- 在 iPhone 上选择回溯起点或本次骑行起点；
- 根据手机轨迹计算返回方向、距离和进度；
- 在圆屏显示简洁的方向、距离和轨迹提示；
- 处理手机定位丢失、轨迹漂移、环路和异常跳点。

### 阶段边界

第一版不要求设备端 GNSS、独立道路级重规划、独立搜索地点或全量离线地图。

### 完成条件

用户能够在 iPhone 记录的真实轨迹上从中途返回起点，圆屏能够提供可理解的回溯提示。

## Phase 5：Can you hear me?

### 目标

实现第一版同行骑手之间的低复杂度短提示，并保持 iPhone 主导的会话管理。

### 工作内容

- 创建或加入同行会话；
- 发送“Can you hear me?”提示；
- 通过圆屏显示或播放提示；
- 提供接收确认、限频、权限和断连状态；
- 保持现有 iPhone 搜索、路线、导航、音乐和轨迹功能可用。

### 阶段边界

当前阶段不预先修改 BLE 协议；如现有通信能力不足，先记录协议需求，另行审批后再实现。

### 完成条件

两台 iPhone 或同行会话能够可靠发送、接收和确认一次提示，并能处理重复发送和连接中断。

## Phase 6：骑行数据 / 情绪化 UI

### 目标

把 iPhone 轨迹和导航数据转化为适合圆屏的骑行数据与轻量情绪化界面。

### 第一版范围

- 本次骑行里程；
- 当前速度、平均速度和骑行时间；
- 轨迹状态、导航状态和必要的定位质量状态；
- 自定义表盘；
- 纪念日、天气、耳机连接状态等轻量卡片或提示。

### 阶段边界

- 数据优先来自 iPhone；不增加设备端独立 GNSS；
- 情绪化 UI 不得遮挡转向、距离和安全相关导航信息；
- 不在此阶段引入账号平台、复杂社交或云端骑行社区。

### 完成条件

用户能够在一次骑行中查看基础数据，并在不影响导航可读性的前提下使用至少一组轻量化 UI。

## Phase 7：可选 Android 支持

### 目标

在 iPhone 第一版稳定后，评估并逐步支持 Android，包括荣耀手机；不让 Android 阻塞 iPhone v1。

### 建议顺序

1. BLE 连接、配对和现有导航状态兼容；
2. 导航状态接收和圆屏显示；
3. 手机轨迹记录、查看和导出；
4. Backtrack 和骑行数据；
5. 后台运行、锁屏、通知和省电策略；
6. 荣耀设备上的真实兼容性测试。

### 阶段边界

不以“理论上支持 Android”作为完成标准。需要至少覆盖实际机型、后台限制、BLE 重连和通知行为。

### 完成条件

至少一套 Android 基础导航和轨迹链路稳定运行，并且不影响 iPhone 第一版的协议和功能稳定性。
