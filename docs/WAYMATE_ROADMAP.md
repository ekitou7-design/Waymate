# Waymate 最小开发路线图

**路线图状态：** 初始规划

**总原则：** 先固定现有项目基线，再确定硬件，再引入 GNSS；轨迹依赖 GNSS，Backtrack 依赖轨迹；iPhone 是第一版主要手机平台，Android 属于后续可选支持。

本路线图不授权提前修改 ESP32 硬件驱动、BLE 协议或大规模项目重命名。每个阶段完成后再决定是否进入下一阶段。

## Phase 0：现有项目基线

### 目标

冻结当前可复用能力和边界，保证后续开发不会破坏已有的 iPhone 导航产品。

### 保留内容

- iPhone 搜索、路线和导航；
- iPhone → BLE → 圆屏导航信息链路；
- 转向、距离、速度、方向显示；
- 466×466 圆屏触摸 UI；
- BLE 通信；
- 音乐控制；
- IMU 方向辅助；
- 现有共享导航核心、UI、测试和后端能力。

### 阶段边界

- 不修改 ESP32 硬件驱动；
- 不修改 BLE 协议；
- 不进行 1.75-G 适配；
- 不进行大规模 MOTO GPS → Waymate 重命名；
- 保留 LICENSE、NOTICE、原作者署名和第三方许可证。

### 完成条件

形成一份准确的当前架构和功能清单，并明确哪些功能属于设备、手机或两端共同承担。

## Phase 1：硬件型号确定

### 目标

在 1.75C 与 1.75-G 之间完成实际采购和技术基线选择，同时保留另一型号的兼容可能性。

### 需要确认

- 最终板卡型号和硬件版本；
- Flash、PSRAM、显示、触摸和 IMU 配置；
- GNSS 芯片、天线、接口、复位和供电；
- 电源按钮、睡眠唤醒和扩展 IO；
- 官方 BSP、ESP-IDF 和组件版本；
- 现有 `board_port` 是否可以抽象为多个硬件实现。

### 阶段边界

在没有真实硬件和确认版资料前，不改驱动，不把 G 版本写入现有默认构建配置。

### 完成条件

形成硬件兼容性矩阵，并明确第一块用于开发和验证的板卡。

## Phase 2：GNSS

### 目标

让设备获得稳定、可验证的独立定位数据，并建立统一的 GNSS 数据模型。

### 工作内容

- 验证 GNSS 芯片、接口、天线和供电；
- 完成定位数据接收和解析；
- 记录有效性、时间、经纬度、精度、速度和航向；
- 处理无定位、弱信号、过期和重新定位；
- 统一 WGS84 等坐标边界；
- 为后续轨迹和里程统计提供稳定输入。

### 阶段边界

本阶段不直接承诺独立路线规划，不把设备变成完整离线导航终端。

### 完成条件

设备能在真实骑行或等效户外环境中持续输出可验证的 GNSS 数据，并能区分有效定位与无效定位。

## Phase 3：轨迹记录

### 目标

基于 GNSS 保存一次骑行的连续轨迹。

### 工作内容

- 定义轨迹点、时间戳、精度和速度字段；
- 定义采样频率、过滤和异常点处理；
- 设计设备存储和断电策略；
- 支持开始、暂停、继续和结束记录；
- 支持查看基本统计、清除和导出；
- 明确隐私和数据删除行为。

### 阶段边界

先不做云端同步、社交分享和复杂地图编辑。

### 完成条件

一次正常骑行结束后，轨迹能够完整保存、读取、清除，并能计算基本里程和时间。

## Phase 4：Backtrack

### 目标

根据已记录轨迹，支持沿原路返回。

### 工作内容

- 选择回溯起点；
- 显示返回方向和距离；
- 显示已走过的轨迹面包屑；
- 处理 GNSS 丢失、漂移、环路和异常跳点；
- 在设备屏幕上提供适合骑行中的简洁提示。

### 阶段边界

第一版不要求完整道路级重规划，不要求独立搜索地点，也不要求全量离线地图。

### 完成条件

设备能够在真实骑行中从中途返回起点，并在短时定位波动后保持合理的回溯方向。

## Phase 5：iPhone 联动

### 目标

将独立 GNSS、轨迹和 Backtrack 能力与现有 iPhone 导航体验连接起来。

### 工作内容

- 明确设备 GNSS 与 iPhone 定位的优先级；
- 设计断连、无 GNSS 和手机无定位时的回退策略；
- 在 iPhone 上查看和管理设备轨迹；
- 将骑行里程、速度和轨迹状态与现有导航状态关联；
- 保持现有 iPhone 搜索、路线、导航、音乐功能可用。

### 阶段边界

本阶段是否需要修改 BLE 协议，必须在需求和数据格式确认后另行批准；当前阶段本身不预先修改 BLE 协议。

### 完成条件

正常连接时，iPhone 导航与设备显示一致；GNSS、手机定位或 BLE 出现异常时，用户能看到明确状态，而不是得到无来源的错误位置。

## Phase 6：Can you hear me?

### 目标

实现同行骑手之间的低复杂度短提示。

### 第一版范围

- 创建同行会话；
- 发送“Can you hear me?”提示；
- 接收、显示或播放提示；
- 提供确认状态；
- 增加限频、权限和断连处理。

### 暂不包含

- 即时语音通话；
- 复杂群聊；
- 默认公开位置共享；
- 没有明确授权的后台录音或持续监听。

### 完成条件

两台设备或两部手机能够在明确会话中可靠发送、接收和确认一次提示，并能处理重复发送和连接中断。

## Phase 7：Android 可选支持

### 目标

在 iPhone 第一版稳定后，评估并逐步支持 Android，包括荣耀手机。

### 建议顺序

1. BLE 连接、配对和协议兼容；
2. 导航状态接收和圆屏显示；
3. GNSS 数据协同；
4. 轨迹查看和导出；
5. 后台运行、锁屏、通知和省电策略；
6. 荣耀设备上的真实兼容性测试。

### 阶段边界

不以“理论上支持 Android”作为完成标准。需要至少覆盖实际机型、后台限制、BLE 重连和通知行为。

### 完成条件

至少一套 Android 基础导航链路稳定运行，并且不影响 iPhone 第一版的协议和功能稳定性。

## 依赖关系

```text
Phase 0 基线
    ↓
Phase 1 硬件确定
    ↓
Phase 2 GNSS
    ↓
Phase 3 轨迹记录
    ↓
Phase 4 Backtrack
    ↓
Phase 5 iPhone 联动
    ↓
Phase 6 同行提示
    ↓
Phase 7 Android 可选支持
```

在尚未拿到最终硬件之前，最安全的开发范围是 Phase 0 的文档、数据模型、状态机设计、主机端测试夹具、iPhone 侧界面和不依赖真实 GNSS 的模拟数据验证；不应据此修改当前硬件驱动或假定 1.75-G 的接口细节。
